# 好好照顾自己 · 普通人的身材管理

一个给忙碌上班族的中文静态网站:记录睡眠、活动、饮食规律和心情,看看长期习惯,而不是盯着某天的体重。

个人作品,非官方产品。由豆包工作制作。

- 纯 HTML / CSS / JavaScript,零构建、零外部依赖
- 双击 `index.html` 即可使用,也能直接部署 GitHub Pages
- 数据只存在当前浏览器的 localStorage,不需要账户、手机号或 API 密钥
- 所有身体数据都可留空,不评价外貌,不承诺减重

---

## 快速开始

1. 打开本项目根目录（即包含 `index.html` 与 `README.md` 的文件夹）
2. 双击 `index.html`,用 Chrome / Edge / Firefox / Safari 打开即可
3. 想先看有数据时是什么样子:页面底部「数据」一节点「打开演示数据」

不需要安装 Node、npm,不需要启动服务器,也不需要联网。页面只在本地读取自己的 `assets/` 文件。

> 如果浏览器因为安全策略不允许 `file://` 页面保存数据(个别 Safari 版本会这样),页面顶部会明确提示「当前浏览器不允许本地保存」。这时可以改用任意静态服务器打开,或部署到 GitHub Pages。Chrome 下已实测可用。

## 功能一览

1. **首屏**:温和的介绍,加一张「今天的一件小事」卡片,可以换一条生活化的小提醒。
2. **按日期记录**:体重、腰围、睡眠时长、运动分钟、心情,全部可选。支持补记过去,不允许未来日期;同一天再保存就是编辑。
3. **自选习惯打卡**:自己添加习惯、自己设每周目标(1–7 次),按本周七天打勾。没有统一的饮水、卡路里或步数要求。
4. **体重趋势**:最近 7 天 / 30 天折线图,带文字摘要和记录次数、平均、最低、最高。图表有 `aria-label` 文字替代。
5. **每周复盘**:统计本周记录天数、习惯完成次数、运动合计、平均睡眠,只谈习惯,不评价胖瘦。
6. **演示数据**:单独的入口、单独的数据键、明显的模式提示条;导出的文件也带 `demo` 标记。
7. **备份**:导出 JSON;导入前校验格式、列出问题、二次确认,可选择「合并」或「替换」。
8. **清空**:必须先经过确认弹窗;取消不会改动数据。

## 数据与隐私

| 内容 | 说明 |

## 演示数据

- 入口在「数据」一节:点「打开演示数据」。
- 演示记录由 `assets/core.js` 在本地生成,不包含任何真实个人数据。
- 演示模式开启后,顶部会出现固定提示条,页面底部也会标明当前模式;此时所有读写都只发生在 `haohao-care:v1:demo`。
- 演示模式下导出,文件名会带 `demo-`,文件内容里 `demo: true`。
- 点「退出演示,回到我的记录」即可回到真实数据,真实记录不会因此多出任何内容。
- 在演示模式下清空,只会清空演示数据。

## 部署到 GitHub Pages

本项目制作时**没有创建仓库、没有联网部署**,以下步骤需要你自己执行。

1. 本地先双击 `index.html` 确认页面可用。
2. 在 GitHub 新建一个仓库(空仓库即可)。
3. 在项目目录执行(把地址换成你的仓库):

   ```bash
   git init
   git add .
   git commit -m "好好照顾自己 v1"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```

4. 打开仓库 **Settings → Pages → Build and deployment**:
   - Source 选 **Deploy from a branch**
   - Branch 选 **main**,目录选 **/(root)**
   - 保存
5. 等一两分钟,访问 `https://<你的用户名>.github.io/<仓库名>/`。

说明:

- 所有资源都用相对路径(`assets/...`),放在仓库根目录或子路径都能正常加载,不需要改代码。
- 不需要 workflow、不需要 `package.json`、不需要开启 Jekyll 之外的处理;本项目没有以 `_` 开头的目录。
- 线上站点与本地 `file://` 的 localStorage 不互通(见上一节)。

## 健康边界

- 这是一般健康习惯记录工具,**不作诊断,不承诺减重效果**,不推荐断食、减肥药或极端热量限制,也不提供个体化的减重处方。
- 未成年人、孕产期、有既往进食障碍,或需要医疗管理(如慢性病、正在用药)的朋友,请先咨询医生、注册营养师等专业人士,再决定是否做记录或调整习惯。
- 页面里唯一引用的健康数字是世界卫生组织《关于身体活动和久坐行为的指南》(2020)中「成年人每周 150–300 分钟中等强度身体活动」的人群层面建议,已标明来源,并明确写了「不是给你的处方」。页面不写 BMI 标准、卡路里目标、减重速度之类没有出处的数字。
- 「今天的一件小事」只是生活提醒,不是医学建议。身体不舒服时,以医生的意见为准。

## 自测记录(真实执行)

```powershell
# 在本项目根目录执行
node tests/core.test.js
node tests/browser-smoke.js
```

实际结果(2026-11-26 最后一次运行):

- `core.test.js`:**32 项检查全部通过**。覆盖日期合法性、跨月跨年、周边界、7/30 天范围、表单校验、超范围数值、未来日期、导入清洗、版本/来源校验、统计、合并、存储隔离、损坏数据、localStorage 不可用降级。
- `browser-smoke.js`:**85 项检查全部通过**。通过 Chrome DevTools Protocol 真实加载页面并操作:
  - 首屏渲染、无脚本异常、`file://` 下 localStorage 可用
  - 新增 3 天记录 → 编辑同一天 → 刷新后回填 → 数据仍在
  - 超范围体重、空日期、未来日期、整条空记录均被拦截,且不覆盖已保存数据
  - 习惯添加、打卡、改目标、重名拒绝、一键添加建议习惯
  - 7 天 / 30 天切换、SVG 图表与文字摘要、每周复盘
  - 演示模式提示条、真实/演示数据互不污染、演示导出带标记
  - JSON 导出、损坏 JSON 导入、超范围数据导入、合并导入、替换导入、删除单条记录
  - 清空数据的取消与确认
  - 390px 与 320px 设备模拟下无横向溢出;Tab 键移动焦点且 outline 可见
  - 表单控件都有可访问名称;页面无 `http(s)` 资源请求

测试过程中真实发现并修好的问题:

1. `summarizeWeights` 的最低/最高值只取了第一个点,改为逐点比较。
2. 习惯渲染依赖的 `Core.habitChecksOn` 没有导出,补上导出。
3. `[hidden]` 被 `.btn { display: inline-flex }` 覆盖,导致「删除这天的记录」按钮一直显示,补 `[hidden] { display: none !important; }`。
4. 首屏脚本引用 `habitSuggestions` 但未缓存该元素,补齐缓存。
5. 5 个记录字段在 4 列网格下挤出一个孤行,改为 5 列并缩短提示文案。
6. 进入演示模式时页面会跳到记录区,移除这段滚动。
7. 演示导出、删除记录、320px 窄屏、键盘 Tab 焦点等场景补充了测试用例。

测试的边界,如实说明:

- 浏览器测试跑在本机无头 Chrome 的**设备模拟**上(390×844 与 320×720,DPR 2),不是实体手机。真机的字体渲染、输入法、日期选择器样式可能有差异。
- 没有在 Safari、Firefox 和旧版浏览器上逐项验证。
- 没有做长时间(多年数据、localStorage 接近配额)压力测试。
- 截图与浏览器测试脚本的中间文件写在临时目录,不进入项目。

## 已知限制

- 单设备、单浏览器;没有账号、同步、多端。
- 日期输入框的显示格式跟随浏览器语言/地区(例如日语环境下显示 `26/11/2026`),内部始终按 `YYYY-MM-DD` 存储。
- 趋势只画体重;腰围只显示最近一次,不做曲线。
- 没有提醒、推送、打卡连续天数、徽章等激励设计。
- localStorage 通常只有几 MB,按每天一条记录估算可以用很多年,但没有做配额预警。
- 不是医疗产品,不能用于诊断、治疗或个体减重指导。
