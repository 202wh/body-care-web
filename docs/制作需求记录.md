## 一、原始需求(要点整理)

1. 主题「普通人的身材管理」,面向忙碌上班族,不制造身材焦虑,不做极端减重;网站暂名「好好照顾自己」;署名只写个人作品。
2. 在本地独立目录新建项目,若已存在则用带日期的新目录,不读取、不修改其他工作文件。
3. 完成 HTML / CSS / JavaScript 与 README;尽量零构建、无外部依赖;双击 `index.html` 可用;可部署 GitHub Pages;资源用相对路径。
4. 功能:首屏温和介绍 +「今天的一件小事」;按日期记录可选体重、腰围、睡眠、运动分钟、心情;自选习惯打卡且目标自设;体重 7/30 天趋势与每周复盘;演示数据入口清晰且与真实数据隔离;JSON 导出/导入、清空确认、空状态与错误校验;只用 localStorage,不发数据到服务器、不需要账户/手机号/API 密钥;适配手机与电脑、键盘可访问、图表有文字摘要、视觉暖白绿色、不用外部图片。
5. 健康边界:不作诊断、不承诺瘦多少、不推荐断食/减肥药/极端热量限制;未成年人、孕产期、既往进食障碍或需医疗管理者提示咨询专业人士;不给个体减重处方;没有可靠来源的健康数字不写;页面说明浏览器清理后数据可能丢失、导出注意隐私。
6. 完成后自测新增/编辑记录、日期处理、导入错误、演示数据隔离、数据持久化和移动布局,修好明显问题,报告真实路径与文件清单,说明由豆包工作制作;README 写清本地打开与 GitHub Pages 部署方法,并留一份制作需求记录;不伪造测试结果。

## 二、交付形态与关键决策

**采用多文件结构,而不是单文件 HTML。** 原因:需求明确要求「HTML / CSS / JavaScript + README」,并要能直接放到 GitHub Pages;拆成 `index.html + assets/` 后职责清楚、便于阅读和后续修改,同时不引入构建步骤。所有引用都是相对路径,`file://` 双击和线上子路径都能工作。

**零构建、零依赖。** 没有 `package.json`、没有打包器、没有 CDN 字体或图标。图标是内联 SVG,favicon 是 data URI,页面不发起任何网络请求。

**普通脚本而不是 ES Module。** `file://` 下 ES Module 会被 CORS 拦,所以 `core.js` / `app.js` 用普通 `<script defer>` 引入;`core.js` 用 UMD 写法,浏览器挂 `window.CareCore`,Node 中可 `require` 做测试。

**逻辑与界面分离。** 日期、校验、导入清洗、统计、存储封装全部放 `core.js` 纯函数里,`app.js` 只负责渲染与事件。这样能在 Node 里真测边界,而不是只靠肉眼点页面。

## 四、数据模型

真实键 `haohao-care:v1:real`,演示键 `haohao-care:v1:demo`,结构相同:

```json
{
  "app": "haohao-care",
  "version": 1,
  "demo": false,
  "entries": {
    "2026-11-26": {
      "weight": 62.3,
      "waist": 80,
      "sleep": 7.5,
      "activity": 30,
      "mood": "平静"
    }
  },
  "habits": [
    { "id": "h-xxxx", "name": "饭后散步", "targetPerWeek": 4 }
  ],
  "habitChecks": { "2026-11-26": ["h-xxxx"] },
  "meta": { "createdAt": "...", "updatedAt": "..." }
}
```

导出文件在外层包一层 `{ app, version, exportedAt, demo, data }`,导入时兼容这种 payload 与裸 store 两种形态。

### 校验规则

| 字段 | 范围 | 说明 |
| --- | --- | --- |
| 日期 | 合法 `YYYY-MM-DD`,不晚于今天 | 用本地时间构造并回读校验,拒绝 `2026-02-30` 这类假日期 |
| 体重 | 20–300 kg,一位小数 | 留空允许;非数字、负数、`62kg` 都拒绝 |
| 腰围 | 30–200 cm | 留空允许 |
| 睡眠 | 0–24 小时 | 留空允许 |
| 运动 | 0–1440 分钟,整数 | 留空允许 |
| 心情 | 固定六个选项或留空 | 不接受未知值 |
| 整条记录 | 至少一项内容 | 防止保存空记录;清空字段请用「删除这天的记录」 |
| 习惯 | 名称 1–14 字、每周目标 1–7 整数、最多 40 个 | 重名拒绝 |
| 导入 | 来源、版本、日期、数值、打卡结构全部校验 | 有问题整体拒绝并列出,不写半坏数据 |

导入时的合并语义:同一天以文件里的字段为准,文件里没写的字段保留原值;习惯按 `id` 合并;打卡取并集。替换则是整体覆盖当前模式的数据。演示导出导入真实模式时,弹窗会额外提醒这份文件是示例数据。

## 五、健康与文案边界

写文案时遵守的几条线:

- 不出现「应该瘦到多少」「标准体重」「BMI 正常范围」、卡路里目标、减重速度等没有出处或容易被当成处方的数字。
- 唯一引用的健康数字是 WHO 2020 年指南「成年人每周 150–300 分钟中等强度身体活动」,页面标明来源,并写明「人群层面参考,不是给你的处方」。
- 页面明确写:不作诊断、不承诺减重、不推荐断食/减肥药/极端限制、不提供个体减重处方;未成年人、孕产期、既往进食障碍、需医疗管理者先咨询专业人士。
- 输入范围(20–300 kg 等)只是防止误输入的边界,不承担任何健康判断。
- 体重摘要只陈述「记录次数、平均、最低、最高、与最早一次的差值」,不写「变瘦/变胖/超标」。
- 复盘固定提示「不评价外貌、不打分、目标可以调低」。
- 不记录身高、不计算 BMI,避免把工具变成身材评判器。
- 「今天的一件小事」全部是行为层面的轻提醒,不涉及疾病、药物、补剂。

## 六、隐私与无障碍

- 页面没有 `fetch` / `XMLHttpRequest`,不接第三方字体、图片、统计;favicon 为 data URI。
- 没有账户体系;不收集身高体重到任何服务器。
- 数据丢失风险与备份隐私写在页面「关于数据与身体,几句实话」和 README 两处。
- 键盘:skip link、原生表单控件、`label` 关联、单选 `label` 包裹、`:focus-visible` 3px outline、弹窗 `showModal` + Esc 关闭 + 焦点回到触发按钮(原生行为)、Tab 顺序自然。
- 图表:`role="img"` + `aria-label`,另配纯文字摘要,不依赖看图。
- 颜色:暖白底、深绿主色,正文对比度足够;不仅靠颜色区分打卡状态(`aria-pressed` 同步)。
- 支持 `prefers-reduced-motion`。

## 七、自测记录(真实执行,不伪造)

### 命令


### 覆盖范围

- **新增/编辑**:新增 3 天记录 → 重复保存同一天 → 覆盖体重且保留睡眠/心情 → 刷新后表单回填、数据仍在。
- **日期处理**:合法/非法日期、跨月跨年、周一为周起点、7/30 天范围、未来日期拦截、补记过去。
- **错误输入**:超范围体重、`abc` 类非数字、空日期、整条空记录;均提示并聚焦,且不覆盖已保存数据。
- **导入错误**:损坏 JSON、来源/版本不符、坏日期、超范围数值、损坏打卡结构、未来打卡;整体拒绝并列出原因。
- **演示隔离**:提示条、`body.is-demo`、独立键、演示内修改 99 kg 不污染真实 62 kg、退出后真实数据恢复、演示导出文件名与 `demo:true`。
- **持久化**:刷新后记录、习惯、图表仍在;清空后 localStorage 键删除、表单回空。
- **移动布局**:390×844 与 320×720 设备模拟,`scrollWidth <= innerWidth`,无横向溢出;主按钮高度 ≥ 36px。
- **键盘/无障碍**:Tab 移动焦点、焦点 outline 3px、所有表单控件有可访问名称、页面 `lang=zh-CN`、skip link 存在。
- **资源**:`performance` 中无任何 `http(s)` 请求。

### 过程中真实发现并修复的问题

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 体重最低/最高值不对 | `summarizeWeights` 只取首点,没有遍历 | 逐点比较后再返回 |
| 习惯列表空白 | `Core.habitChecksOn` 定义了但忘记导出 | 加入 `core.js` 返回对象 |
| 「删除这天的记录」一直显示 | `.btn { display:inline-flex }` 覆盖了 `[hidden]` 的 UA 样式 | 增加 `[hidden] { display: none !important; }` |
| 首屏脚本报错 | `habitSuggestions` 未加入元素缓存 | 补缓存项 |
| 5 个记录字段挤成 4+1 两行 | 4 列网格容纳 5 个字段 | 桌面改 5 列,并缩短字段提示 |
| 进入演示后页面跳动 | `switchMode` 里多余 `scrollIntoView` | 移除 |
| 单测期望值写错 3 处 | 测试自身把跨日差值符号、睡眠均值、带权重天数算错 | 修正测试期望,而非改实现 |
| 无头截图 390px 右侧被裁 | Chrome 窗口最小宽度造成截图裁切,非页面溢出 | 改用 CDP 设备模拟复核 `scrollWidth`,并补 320px 用例 |
